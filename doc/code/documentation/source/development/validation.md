# Validation and scientific recovery

## Purpose

A description of the methods used to select the examination, to interpret the evidence and to re-use and compare the results under the same scientific conditions, with specific modifications.

## Scope

Entering and completing tasks requires the official interface and protocol definition.

## Check according to use selection

This is developed using a functional scene that will answer this question. First, you determine the actions that the results support, and then generate, read and use it from the actual entry; the contents that need to be saved are reread after the original execution. The relevant incomplete scenes include the actual object, the known cause, the impact and the next step, by which the caller fixes the conditions, continues the task or uses the results already achieved.

Full offline testing, installation and packing checks are used by [publishing validation](../../../../../.github/workflows/release-validation.yml) and missions that clearly require an overall inspection. Models and GPU experiments select resources and budgets according to the corresponding tasks.

## Understand the evidence.

The registration information describes the optional configuration, synthesizes the input description of the software behaviour examined, and authentic model records describe the observation of the corresponding weights, data and protocols. Scientific findings use evidence consistent with their problems and protocols. Historical records are read by date and input; current model information is available in [models and SAE] for](model-support.md) and [layered observation log](verified-model-matrix.md).

## Reuse & Compare

Use the same model as SAE identity, input, location, classification and indicator definition; associated samples calculate uncertainty by original grouping. Cache and resume the identity check already available using the module under which they belong. The results vary and are not comparable. The source, configuration and original values used are traceable.

The software is published in the [publication process](release-process.md)].
