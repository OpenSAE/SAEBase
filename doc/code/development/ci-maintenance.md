# 持续集成与科研验证

## 目的和主要功能

说明项目日常检查、中央接入及发布验证分别确认哪些结果。

## 适用范围

适用于维护工作流、选择检查范围和解释验证结果。

## 维护检查功能

新增或修改检查时，先确定开发者收到结果后需要定位什么、修复什么或继续哪项工作，再选择检查对象和结果内容。所需原因、涉及文件及处理建议从负责检查的模块提供，汇总过程保留它们。检查场景从实际调用入口读取结果并使用这些信息处理问题，按本次改动选择适用的情形。

## 日常检查

[工作流](../../../.github/workflows/ci.yml)根据 Git 变更选择检查。文档和技能说明按内容审阅，项目内接入资料使用本地接口检查，科研代码使用相应产品测试。缺少变更基线时运行项目内检查。

日常工作流使用仓库内容及所需开发依赖；中央环境查询由明确的中央接入任务调用。相关结果通过 `ci-required` 汇总。

## 中央接入

中央入口在[接入说明](../../../.github/CONTRIBUTING.md)。普通查询使用当前绑定和实际接口，需要固定版本的验收显式传入预期引擎文件。

## 发布与科研结果

[发布验证](../../../.github/workflows/release-validation.yml)由明确选择的源码提交启动，检查软件安装、完整离线功能、打包和选定方法。产物与实际成功的验证记录关联。正式发布使用[发布流程](release-process.md)。

[科研方法回归](../../../.github/workflows/research-regression.yml)使用固定原版 SAR 和 RSS 源码检查集成。[上游兼容检查](../../../.github/workflows/upstream-compatibility.yml)用于观察上游变化。

软件测试、合成模型、真实模型实验和科研结论各自保存对应的实际证据，供相关维护和科研任务使用。
