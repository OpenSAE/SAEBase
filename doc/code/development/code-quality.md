# 代码质量与测试

## 目的和主要功能

说明局部格式、类型检查及测试结果的使用方法。

## 适用范围

适用于 Python 开发、提交检查及测试结果报告。

## 局部开发

按需要安装 `python -m pip install -e ".[dev,quality]"`。检查采用本次涉及的文件和功能范围。制定功能时选定结果的实际使用场景，再据此选择或补充检查：通过正式入口取得结果，保存后重新读取，并使用其中的信息完成后续操作。失败与部分完成情形按实际需要确认原因、影响和处理建议能够被使用，已有测试优先复用。临时测试完成用途后删除，有持续用途的进入正式测试目录。

`pre-commit install` 启用提交检查。已纳入类型检查的模块只在其发生变更时检查；新增 Python 文件由 `scripts/quality.py` 按暂存范围选择并检查。Ruff 使用 `0.15.22`。

## 工具与检查范围

Ruff 和 mypy 当前覆盖 `saebase/seed.py`、`datasets/artifacts.py`、`datasets/artifacts.py` 和 `tasks/benchmark/metrics/registry.py`。在这些文件发生修改时执行相关检查，其他文件依据具体修改处理。

新增文件检查会格式化明确选定的新增文件，再执行格式与语法规范检查。已有文件的格式修改按当前任务范围进行。

## 项目级测试

完整离线测试、覆盖率及打包检查用于发布准备或明确需要整体检查的任务。覆盖率描述实际执行范围，功能是否完成由具体输入和结果判断。

软件工具结果、真实模型运行与科研结论分别保留其实际依据，供对应的开发和科研任务使用。
