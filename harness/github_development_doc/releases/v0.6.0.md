# SAEBase v0.6.0 — Unified SAE Research Workspace

SAEBase v0.6.0 integrates the OpenResearch execution and Harness layers into the existing SAEBase toolkit, while preserving the original public Python API, nine command names, checkpoint identities and previous software release history.

## Highlights

- **Seven executable LLM SAE workflows:** capture, intervene, generate, circuits, explain, benchmark, and train, with independent task registration and source-linked results.
- **Unified research execution:** SAEBase research runtime with Hydra dispatch, bundled prompt dataset sources, Gemma-2 2B model adapters, experiment identities and output records. The standard third-party Hugging Face `datasets` import remains available.
- **Agent governance and Atlas:** Core, Knowledge, Code, Environment and Context trees; source-linked AST documentation; scoped Cursor rules and Agent Flow review; local Chinese/English language selection.
- **Compatibility:** the existing `saebase` CLI and original model/SAE catalog are retained. the research runtime, prompt dataset modules, and Hydra YAML config resources are included in the new wheel for use outside the source checkout.
- **Scope:** this release is exclusively for LLM/SAE research and does not ship the earlier imported image-classification example projects.

## Verification and evidence

The candidate must pass the six required exact-source Python 3.11/3.12, packaging, analysis dependency, localization-native and quality CI checks on `main`. The integrated branch additionally checks Hydra task composition, Harness/Atlas exports and source-only regression tests.

An RTX 5070 (12 GB) validation on Gemma-2 2B and a Gemma Scope SAE is documented in the [GPU acceptance report](../gpu-acceptance-20261027.md). That report records genuine activation capture, feature edits, generation, benchmark metrics, a native raw circuit-tracer graph, a small explanation-generator smoke and a two-step native SAE training/checkpoint-reload smoke.

**Scientific limits matter:** a raw circuit graph is not yet the normalized/causally validated graph; no independent semantic correctness was established for generated feature explanations; two-step SAE training is not a full training-quality study. The first GPU report and its follow-up D1–D6 fixes and remaining blockers are documented separately. Source code or CI success is not scientific validation of every model, feature or intervention.

## Install

Python **3.11 or 3.12**:

```bash
git clone --branch v0.6.0 https://github.com/OpenSAE/SAEBase.git
cd SAEBase
python -m pip install -e ".[analysis]"
python saebase/examples/quickstart/public_api_offline.py
python -m saebase.runtime.train --cfg job
python -m saebase.runtime.train task=benchmark --cfg job
```

The `--cfg job` examples compose configurations without downloading a model or launching a GPU experiment. Real execution requires appropriately pinned model/SAE weights, compatible dependencies, resource approval, and explicit task options. Use `conf/sae_research.yaml` for the seven research tasks; the previous `saebase` entry points remain supported.

See the [integration guide](../openresearch-integration.md), [Harness](../../README.md), [GPU report](../gpu-acceptance-20261027.md) and [release process](../release-process.md).

## Distribution and safety

The GitHub software Release contains the CI-tested **wheel**, **sdist**, **release-evidence.json**, and **SHA256SUMS**. No pretrained LLM/SAE weights, private prompts, GPU raw datasets, personal secrets or cloud access tokens are distributed. No PyPI upload or guaranteed hosted GPU service is implied. Previously published version tags and scientific archives remain immutable.

This is a source- and software-integrity release, not a claim of generalized interpretability or benchmark validity.
