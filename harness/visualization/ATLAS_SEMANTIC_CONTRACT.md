# SAEBase Atlas 五树生成和语义验收合同

这份合同约束 Core、Knowledge、Code、Environment、Context。它先于文案生成、分组和发布运行；任何异常都必须保留具体 node ID、父节点、源证据和失败原因。

## 一、树如何生成

1. **先实体，后概念。** Core 表示已实现的架构职责；Knowledge 表示有科学含义且有证据的方法；Code 表示研究功能及其真正的 Python 实现；Environment 表示实际可观测的设备和运行条件；Context 表示权威术语及稳定 ID。各树承担独立的问题，不得相互复制同一层的内容。
2. **功能节点是语义单位。** 一个功能必须有可区分的对象、输入、操作、产物或约束。多个函数协同实现同一功能时，用一个功能节点列出全部函数接口。源文件或函数名只作证据，不能作为创造新功能的理由。
3. **三层职责分开。** 标题命名功能及其区别；卡片摘要说明实际输入、处理、结果或约束；展开面板提供额外事实、完整签名、参数、返回值、证据和 Context 定义。父节点概括共同目标，子节点表达差异，不得复述父节点。
4. **Context 和出处是必要条件。** 新造的功能分组具有可解析的权威 Context 术语 ID、真实源码或结构证据，以及经审定的中英文标题和摘要。不得创建无依据的第 N 组、按行号切分、其他接口、相关操作等占位节点。
5. **数量限制不是分组依据。** 直接子节点优先不超过十个，上限二十个。超限只能通过真实科研或工程职能分层。分页仅影响屏幕展示。
6. **合并与保留。** 多个子函数的标题和摘要相同，先核查源码的输入、输出及副作用；如果确属同一职能，将它们的完整接口、参数、返回类型、源码路径及符号 ID 归入父功能节点。原仓库代码与科学实现保持不变。不能判断等价时标记待审，禁止仅修改动词来“通过”测试。
7. **辅助接口不冒充功能。** 缺少独立、经审核的摘要的类方法或模块函数，默认展示为其拥有者的技术接口。显式审定的科研接口及被 Core/Knowledge 引用的源码实体仍保留独立身份。

## 二、生成后检查什么

| 检查层 | 必须核查 | 判断原则 |
|---|---|---|
| 节点身份 | ID 唯一、类型与树一致、状态正确、无虚构节点 | 违反即失败 |
| 标题 | 非空，准确命名独立对象或行为 | 标题与摘要正规化后完全相同即失败 |
| 卡片摘要 | 具有输入、处理、输出或约束中的真实事实 | 纯重复、通用“负责标题”模板或来源提示标记为无效 |
| 展开解释 | 信息相对摘要有增量 | 重复文本不渲染，不生成第二份说明 |
| 父子关系 | 父节点概括，子节点职责互斥或互补 | 同父标题与摘要同现时审查合并 |
| 近似意义 | 中英双语的相似度与操作契约 | 相似度只能触发人工审查，不能自动证实等价 |
| 函数与类 | 原始 AST 符号、签名、参数、返回、定义行、来源及引用 | 合并后仍能在拥有者接口明细访问完整定义 |
| Context | 所有显式 ID 都能在权威术语表中解析 | 不得凭同名文字臆造术语 |
| 边与覆盖 | 引用端点存在、层级无环、没有遗失被引用的源码 | 无声丢失即失败 |
| 双语 | 节点标题和摘要忠实对应，专业词汇与 Context 一致 | 中文、英文分别核查 |
| 资源与环境 | 设备/测试状态有真实来源，历史检查不变成当前运行能力 | 缺失证据不猜测 |

## 三、错误处理、报告和 CI

- 建立跨五树报告：相同标题/摘要、重复展开、相同父子职责、同级精确重复、潜在近义、模板化说明、Context 缺失、源码引用缺失、循环和过量直接子节点。每个问题列出 ID、所属树、父节点及证据。
- **硬拒绝规则**：每个节点标题与卡片摘要正规化后必须不同；新生成节点无 Context / 来源时拒绝；合并造成引用断裂时拒绝；已审核的同级节点不可有相同或高度相似的职责。
- 历史弱语义节点要有统计清单，逐批通过源代码复核消除。未经核实的近义判断只作为审阅候选，不可批量静默重命名或丢弃。
- 在 CI 中先构建全部五棵树、检查结构和双语，再运行跨树语义审计与 Chromium 页面测试。源节点及源码细节保留不变；部署到 Pages 后还须核对真实站点版本。
