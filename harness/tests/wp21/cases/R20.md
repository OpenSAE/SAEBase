# R20 真实多阶段实验与故障后交接

在一个自给定工作流中贯通真实capture、intervene、benchmark及失败后重试，把每阶段结果关联到实际输入与上游证据。无需其它19位agent的代码或结果。

## 基线与既有行为

本题直接组合当前已存在的真实API，不能依赖R02–R19修复；如果基线真实组件有缺陷，应保留失败并归因为产品/环境/规范问题，不能自行改受保护规则或伪造通过。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 从common train选前2条用于冻结一个非零feature，从validation选前4条作为完整pipeline测量集合；冻结source/config/model/SAE/tokenizer/site/input身份，不使用test调参。
2. 阶段A通过真实capture_features采集4条输入，保存activation/codes及完整sample身份。
3. 阶段B用evaluate_edit在相同4条输入执行identity和该feature置零的消融，保存真实logits差异与对阶段A记录的引用。
4. 阶段C用实际BenchmarkConfig与saebase.benchmarks.runner.execute(real=True)执行core.l0、core.reconstruction_mse、intervention.logit_delta_l2，条件含identity与同feature ablate；用真实pair loader且记录其来源，不注入toy。
5. 每阶段记录parent artifact hash、自己的config与产物hash；benchmark的sample、site、checkpoint与A/B一致，指标独立复算可对上，明确每种指标的sample unit。
6. 在另一个attempt完成A后注入一次已声明的B阶段失败（例如不合法feature ID），确认后续C不产生成功声明；保留失败事件、退出码及已经提交的A产物。
7. 新attempt修正为冻结合法feature并从已验证A证据交接，完成B/C。若API实际重新前向必须如实记录，不把引用旧证据说成零计算缓存命中。
8. 输出阶段表、原始数值、可浏览报告与失败归因；无需优化指标或宣称研究结论。

## 必须通过的正例

1. A/B/C全部执行真实SAEBase对应组件，原始输入、checkpoint与site一致。
2. 完整pipeline每个metric的n_requested/n_valid/status与真实样本数一致，undefined/blocked不当作completed。
3. parent references确实能解析到既有字节及hash，不是随手填路径。
4. 注入故障确实阻止成功下游；新attempt完成后旧失败日志与A产物保持。
5. 最终结果可从冻结输入、公开命令和真实中间产物独立重放。

## 必须检查的负例

1. 以状态JSON或模拟张量代替任一实际阶段判失败。
2. 跨model/SAE/site/input引用旧capture或漏检parent hash判失败。
3. B失败后仍发布成功C、覆盖失败日志或把partial当completed判失败。
4. 删除一条样本但仍报完整n_valid、只有report没有原始metrics判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
