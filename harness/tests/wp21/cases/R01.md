# R01 真实采集、恒等写回与特征消融

使用现有 SAEBase 接口完成一个可复核的真实 Gemma-2 2B 小实验，建立本轮真实运行基线。现有 configured_only 与 synthetic quickstart 均不能作为本题完成证据。

## 基线与既有行为

本题验证现有接口，不预先修复题目目标功能。ModelAdapter 与 FeatureSnapshot 是真实运行入口；real=True 或一份 PASS JSON 均不能证明 checkpoint 执行。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 从冻结 common/prompts.jsonl 取前 8 条固定记录；保留 sample_id、prompt_group_id、split 与完整文本 SHA256，每条按冻结 tokenizer 实际编码后最多 96 tokens，超限明确拒绝而非静默截断。
2. 加载已冻结的 gemma2_2b_base / gemma2_2b_pt_l25_canonical，layer=25，记录真实 checkpoint 文件身份、tokenizer、dtype、device、依赖版本和源码身份。
3. 对每条记录调用 capture_features，保留 activation、codes、reconstruction 的可复算小型张量文件及 shape/finite 统计。
4. 通过 ModelAdapter.assert_identity_patch，并独立保存原始 forward_logits 与原 activation 写回 logits 的最大绝对误差；使用 rtol=1e-4、atol=1e-4。
5. 在第一条记录选择绝对值最大且非零的 feature，平局按较小 feature_id；冻结该选择，再用 evaluate_edit(replacements={id:0.0}) 对同一条记录做消融。若所有 codes 为零则记为真实观测，转用下一个固定输入，全部为零则报告 BLOCKED_NO_ACTIVE_FEATURE。
6. 用实际 snapshot 与 decoder 复算被修改 code、activation 和 logits 差异；消融误差或无变化按实际记录，不预设改善指标。
7. 保存完整命令、退出码、原始产物、正反检查与范围差异；本题可保持产品源码无改动。

## 必须通过的正例

1. 8 条输入各有且仅有一个对应 capture 记录，输入 ID/hash 与真实 tokens 对齐。
2. activation width、SAE code width、重建 width 与加载对象一致，全部 finite。
3. 恒等写回满足冻结 allclose 容差，误差来自真实 logits。
4. 消融后的选定 code 为 0，未选 code 和重建残差按 evaluate_edit 原有规则保留。
5. 相同冻结输入与 checkpoint 的重复调用在声明容差内一致。

## 必须检查的负例

1. 空 prompt、超预算 prompt 在实验 runner 中拒绝并保留失败退出码。
2. 越界 feature_id 传入真实 API 必须报错，不能裁剪成合法 ID。
3. 未知 hook 或越界 layer 在实际 adapter 中拒绝，不能返回空张量当成功。
4. 缺少 checkpoint、输入 manifest 不匹配时记为 BLOCKED/FAIL，不能换成随机或 toy 权重。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
