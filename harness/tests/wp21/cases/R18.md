# R18 真实实验产物完整性与稳定配置身份

为真实SAEBase run增加可检查的artifact integrity manifest和canonical配置身份，检测字节篡改、缺失及配置变化。新身份与现有runtime run.json配置hash并列保留。

## 基线与既有行为

runtime已有按YAML文本计算的config_sha256，mapping顺序可能影响它；本题新增独立canonical identity工具，禁止在考试中改共享runtime或重写旧身份。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 先经真实capture运行common前2条，获得规范experiment leaf的metadata、metric/tensor与配置产物。
2. 在saebase/tools/experiment_integrity.py实现薄的manifest create/verify工具；输入为一个已存在的本题owned run，路径必须在明确experiment root内，拒绝symlink/traversal。
3. 冻结入清单的不可变文件集合，条目包含相对路径、字节大小、SHA256；manifest不包含它自身，明确排除尚会追加的命令日志、tmp与其它非目标文件，列明排除策略而非事后随意跳过。
4. 将完全resolved的实验语义配置转为规范JSON（字典key排序、固定分隔、拒绝NaN），生成canonical_config_sha256；声明哪些临时输出路径/时间字段不属于实验语义配置，并给出固定字段列表。
5. 保留metadata/run.json现有config_sha256及其名称/含义。新增canonical hash写在独立integrity manifest中，不编辑saebase/runtime。
6. 验证未修改真实run通过，再在独立副本分别修改一个metric字节、删除一个tensor、改seed/参数；检查具体拒绝原因。
7. 仅重排配置字典key应保持canonical hash；改变实际seed/model/input/参数必须改变它。校验原始run未被负例污染。

## 必须通过的正例

1. manifest列出的路径确实存在，大小/hash来自真实字节，非手写期望值。
2. 真实原run校验通过；canonical hash可独立重算。
3. mapping key重排不改变canonical identity，实际参数变化改变。
4. 现有runtime config_sha256原值保持，新增字段不冒充旧hash。
5. 负例在独立副本执行，原始真实run的hash始终不变。

## 必须检查的负例

1. 一个字节篡改、缺文件、同名不同内容均失败。
2. manifest里的../、绝对路径、symlink外逃拒绝。
3. NaN配置、重复文件条目、未声明跳过文件拒绝。
4. 把空manifest或只验证文件名当完整性通过判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
