# R19 安全归档、精确清理与恢复一个真实 run

对一个已完成真实运行提供归档、校验、精确清理和恢复，证明操作只影响明确拥有的单个run，不跟随symlink或越界路径。

## 基线与既有行为

现有runtime能建结构化run并保护覆盖，未提供本题所需的通用archive/cleanup/restore闭环。实现放saebase/tools，runtime保持受保护。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

## 具体执行步骤

1. 先创建本题独立真实capture run并保存至少1条模型测量。旁边建立另一个run目录与sentinel文件，记录其hash作为保护对照。
2. 在saebase/tools/experiment_archive.py实现create/verify/cleanup/restore，输入必须包含明确experiment root与一个owned run相对路径；根据metadata/run.json核对run身份。不得允许root、dataset父级或任意目录整体清理。
3. 归档内写入逐文件相对路径、size、SHA256与run身份manifest；只处理常规文件/目录，不沿symlink进入其它位置；本题archive自身放在目标run之外。
4. 完成archive并独立验证后，cleanup才可删除该精确run；cleanup前再次核对源bytes与归档identity一致，拒绝中途变化。
5. restore到原目标的不存在/空位置，先安全展开到受限临时目录并验完整性，再提交；已存在非空目标拒绝覆盖。
6. 重读恢复后的原始capture数据与metadata，逐文件hash等于归档前；不要求重跑模型。
7. 分别测试../、绝对路径、symlink到sentinel、坏hash/截断archive、冲突目标；所有失败不得修改sentinel、兄弟run或原始归档。

## 必须通过的正例

1. 操作前有真实SAEBase运行与可读原始产物。
2. archive/verify成功后精确cleanup仅删除指定owned run。
3. restore逐文件bytes一致且原metadata语义可读。
4. 兄弟run与sentinel全过程hash不变。
5. 归档工具独立自足，不依赖R18另一个agent的实现。

## 必须检查的负例

1. 任何../、绝对路径、symlink或祖先目录目标拒绝。
2. 损坏/截断/篡改archive、异常成员名或重复member拒绝。
3. 已有非空restore目标、未验证archive的cleanup拒绝。
4. source在create后到cleanup前变化必须失败，禁止误删新数据。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
