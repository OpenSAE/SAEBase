## 具体执行步骤

1. 先保存一次baseline真实运行：conf/task/capture.yaml的top_k=10已公开，但operation固定min(10,codes.numel())；显式top_k=3时返回10个feature，记录这一错误行为及其原始codes。
2. 在 capture operation 内读取并严格验证 top_k。接受非 bool 的正整数；实际输出数量为 min(top_k,d_sae)，默认 10。
3. 本题固定六个完整真实配置运行，使用同一prompt/checkpoint/layer/dtype且独立experiment leaf：baseline top_k=3；修复后top_k=3、7、10；修复后省略top_k；修复后top_k=d_sae+1。其中d_sae从冻结真实SAE读取。
4. 用保存的原始 codes 独立计算按绝对值下降的 top features；相同绝对值的 feature_id 顺序固定为升序。输出的 activation 保留原符号。
5. 以baseline硬编码10的实际codes与源定义作为旧默认行为依据，比较修复后top_k=10和省略top_k的结果；除明确的平局排序规则和requested/effective参数记录外，原字段含义与数值保持一致。
6. 在启动模型加载前验证scalar类型和正范围；合法的大k在获得真实d_sae后显式截至d_sae，记录requested_k和effective_k。负例在加载前拒绝，不额外占用这六个model trial，但其命令、退出码与耗时仍计入本题总预算。

## 必须通过的正例

1. k=3、7、10 分别返回 3、7、10 个 feature，并与保存的真实 code 数值一致。
2. 修复后省略top_k与显式10等效，原字段active_count、feature_count、reconstruction_l2含义保持；六个真实配置都有原始证据。
3. 输出排序按绝对值下降、feature_id 升序处理平局。
4. top_k 大于 d_sae 时返回全部 d_sae 个 feature，requested/effective 数量明确。

## 必须检查的负例

1. top_k=0、-1 在模型加载之前失败。
2. top_k=true、1.5、'3' 等错误类型不能被 int() 静默接受；Hydra 会转成 int 的正常 CLI top_k=3 属于合法值。
3. 任何 fixture 或独立 runner 绕过 task 配置后直接改变结果条数不能作为参数贯通证据。
4. 无真实 codes 的手工 top_features JSON 不构成正例。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
