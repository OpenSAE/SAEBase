# R10 新增已注册的 feature summary 任务

新增 wp21_feature_summary task，读取多条真实prompt并汇总SAE feature统计；任务实现放入既有capture源码类别，使用现有TaskModule/Registry/Hydra链。

## 基线与既有行为

当前Registry支持新TaskModule，七个现有SAEOperationTask使用固定操作列表；本题新task采用公共TaskModule合同，自行明确返回EvaluationResult，避免混用legacy dict/result路径。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 实现TaskModule子类并通过tasks/plugins.py注册唯一task key wp21_feature_summary，配置放conf/task/wp21_feature_summary.yaml；源码放tasks/capture/wp21_feature_summary.py，不新建第八个顶层task目录。
2. 明确task.path必须以wp21_feature_summary开头，source归属capture和运行task名是不同职责。新task自己使用公共load_registered/capture_features，不向七操作固定列表硬塞第八操作。
3. 配置max_prompts默认4且范围1..8，feature_limit默认5且范围1..20；本题实际使用冻结common的前4条，输入来源与dataset identity完整。
4. 为新task补齐仅必要的dataset/model兼容声明，使runtime.train的registry/config验证通过；不放宽未知task或未知model。
5. 每条保存真实codes，定义per_prompt_active_count=count_nonzero(codes)，全体mean_active_count为其算术均值；top_features依据各feature的mean_abs_activation排序，平局feature_id升序。
6. 返回saebase.results.EvaluationResult并将统计写入规范metrics/tables目录；记录实际sample IDs/count。
7. 从fresh process通过python -m saebase.runtime.train task=wp21_feature_summary task.execute=true运行，而非仅直接调用类。

## 必须通过的正例

1. registry列举、Hydra选择、compatibility验证、runner dispatch、真实数据消费与结果均贯通。
2. 4条真实codes独立复算的mean_active_count与mean_abs_activation一致。
3. EvaluationResult.ok、task、model_key、sae_key、summary与产物相符。
4. 原capture和未知key拒绝行为保持。

## 必须检查的负例

1. 重复task注册必须拒绝，不可覆盖旧task。
2. 未知task/model/dataset不能静默映射到本task。
3. max_prompts=0/9或feature_limit=0/21、bool等错误值在模型加载前拒绝。
4. 仅新增一个未被registry/runner调用的辅助函数不能视为新增task。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
