# R17 训练 seed 贯通与短程 SAE 复现

修复native SAELens adapter把seed固定为0的问题，完成三个每次1024训练token的真实小SAE训练，并在训练外固定输入上重载检查。这里只验证训练链与seed行为。

## 基线与既有行为

tasks/train/backend/training.py 当前SAELens runner seed=0；train_batch_size_tokens=plan.batch_size、training_tokens=plan.steps*plan.batch_size。1024token只是工程训练烟测，指标无需达到科学质量门槛。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_training`。本题没有额外instructor seed。

## 具体执行步骤

1. 基线_saelens_train构造LanguageModelSAERunnerConfig(seed=0)。在TrainPlan新增严格非bool非负int的seed，历史默认0；task路径将cfg.seed传入plan，若显式plan.seed与cfg.seed冲突则拒绝。
2. 将SAELens runner seed改为plan.seed，并使plan.json、checkpoint登记和恢复身份包含该seed；旧plan无seed按0解释。修改范围仅native training/task-owned代码，不改共享runtime。
3. 固定backend=saelens、architecture=topk、d_in=2304、d_sae=64、k=8、hookpoint=blocks.25.hook_resid_post、steps=16、batch_size=64、ctx_len=16、distributed_gpus=1。SAELens训练token数是steps×batch_size=1024，不能再乘ctx_len。
4. 从common train的12条构建本地训练corpus；如需重复以满足原生loader，确定性重复并记录每条原sample_id/prompt_group_id。validation/test样本不得进入训练。model与dataset revision/内容hash冻结，model_dtype及sae_dtype由gemma_training环境锁定，记录实际dtype。
5. 执行seed=7、7、11三次真实原生SAELens训练，分别新run_name/输出目录，每次最多1024训练token，合计最多3072；用进程监督执行time budget，不能以SAELens函数内timeout字段未强制为由无限运行。
6. 用原生SAE.load_from_disk重载每个实际checkpoint，再以冻结Gemma真实activation对common validation的6条做encode/decode，报告MSE与L0，记录文件hash与tensor统计。
7. 相同seed两次在冻结同环境下比较checkpoint张量，预设rtol=1e-4、atol=1e-5；不满足则保留失败与原因。seed11至少证明已传到原生配置且真实训练发生，比较实际权重，不能仅靠目录seed。
8. Sparsify不属于本题真实运行；保持既有默认seed=0行为。若新seed字段可传给Sparsify而未支持，非零seed必须明确拒绝，不能悄悄忽略。

## 必须通过的正例

1. 三次真实native训练均有原生日志、实际checkpoint与重载证据，每次训练token1024、总3072以内。
2. plan/task/native runner seed贯通，默认0兼容，冲突拒绝。
3. 同seed checkpoint张量在预设容差内一致；不同seed配置真实不同且有实际权重比较记录。
4. heldout6条真实activation上的重载SAE输出shape正确、finite，MSE/L0由原始输出复算。
5. 训练、validation的sample和group无交叉。

## 必须检查的负例

1. 负seed、bool、非整数seed与task/plan冲突在训练前拒绝。
2. 越过1024训练token/单次、3次总运行、单GPU或明确时间预算必须阻止。
3. 随机伪造checkpoint、仅改seed标签、以synthetic model替代Gemma判失败。
4. 训练corpus含validation/test或旧结果目录被覆盖判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
