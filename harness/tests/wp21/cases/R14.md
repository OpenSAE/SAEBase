# R14 让 capture 按记录批量消费输入

修改现有capture，使task.max_prompts默认1、范围1..8，按真实dataset记录执行并保存对应IDs。保持原单prompt接口的兼容。

## 基线与既有行为

当前tasks.sae_runtime._prompt只read_first_prompt，capture只消费一条；本题修改task-owned operation，不改shared runtime或预先依赖R02/R03。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 具体执行步骤

1. 记录基线_prompt只返回数据集第一条；在capture新增max_prompts默认1，严格接受非bool整数1..8。
2. 当task.prompt非空时沿用原单prompt行为，max_prompts只能为1；用户给定单prompt与批量请求同时出现时明确拒绝，避免复制同一prompt。
3. 当task.prompt为空时，使用datasets.prompts.read_prompts读取完整records；按文件原顺序取前N条，若可用条数不足N则报错，不静默少跑。
4. 对common数据准备一份明确身份的IOI可用prompt文件，保留sample_id/prompt_group_id/split；配置dataset.prompt_file指向它，并用max_prompts=1、4、8真实运行。
5. 一批内只加载同一真实model/SAE一次，对每条分别capture；每条结果绑定sample_id与prompt SHA。
6. max_prompts=1保留原顶级summary字段；批量返回records与n_requested/n_completed，并说明顶级summary是否仅保留单条模式，避免把第一条冒充aggregate。
7. 原始records含重复ID、空prompt等情况先验证后运行，不生成部分成功的完整声明。

## 必须通过的正例

1. N=1、4、8实际运行条数一致；所有sample IDs、order、prompt hashes对应输入。
2. 单条模式与原返回字段/数值兼容。
3. 批量记录分别来自真实前向，而不是复用第一条张量。
4. 同checkpoint加载复用与每条真实capture可由调用日志及原始tensor复查。

## 必须检查的负例

1. N=0、9、true、1.5等非法值在模型加载前拒绝。
2. 不足N条、重复sample_id、空prompt拒绝且n_completed不伪造。
3. 非空task.prompt与N>1冲突明确失败。
4. 输入中出现不同prompt但全部结果复制第一条的错误实现必须被检查发现。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
