# R12 新增实际执行的 reconstruction subtask

为benchmark增加task.subtask=reconstruction的真实执行分支，计算真实activation重建MSE。task.path负责目录，task.subtask负责行为选择，两者必须分别落实。

## 基线与既有行为

基线没有独立subtask注册；experiment_paths.task_components只管目录。应在task-owned operation中增加明确dispatch，不修改共享runtime。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 具体执行步骤

1. 新增task.subtask默认空字符串，空值保留现有benchmark_config驱动完整benchmark行为；仅新值reconstruction进入小型重建子任务。
2. 定义reconstruction分支通过真实load_registered/capture_features取得snapshot，指标为mean((activation.float()-reconstruction.float())**2)，不把vector norm当MSE。
3. 设置task.path=benchmark/reconstruction并通过实际task.subtask dispatch执行；单独改path不得改变运算。
4. 使用common前4条prompt，四个独立run leaf真实执行该subtask，保存原始向量和每条MSE。
5. 额外用一条真实prompt的小型BenchmarkConfig调用默认benchmark路线，证明新增分支保留原默认能力。
6. 未知subtask和无效类型在加载模型前失败，error记录明确说明受支持值。
7. 当前默认benchmark loader未把task.device传给load_registered，因此默认路线实际使用CPU，即使task.device=cuda。记录实际device、内存与用时，不宣称已走GPU路线；硬件资源不足记为环境阻塞，不越权修改shared runtime或backend runner。

## 必须通过的正例

1. subtask=reconstruction真实执行，并产生4条可独立复算MSE。
2. task.path层级和subtask值在run/config身份中同时出现，含义明确。
3. 同path却无subtask参数时不会偷偷改为reconstruction行为。
4. 原默认benchmark_config路线用真实checkpoint完成至少core.l0或core.reconstruction_mse一项。
5. 默认benchmark回归记录实际加载device；配置写cuda而实际CPU的差异明确可见，不伪报GPU执行。

## 必须检查的负例

1. 未知subtask、null/列表等不支持类型拒绝，不能回退默认然后声称成功。
2. 仅写入benchmark/reconstruction目录而实际执行旧函数判失败。
3. 把squared L2或norm写成MSE，检查器应发现。
4. 默认benchmark_config缺失依旧明确报错，不因新分支而吞掉。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
