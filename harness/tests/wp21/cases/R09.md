# R09 删除临时模型 provider

删除 seed 中 ext.wp21.retired_gemma 实验provider与配置入口，保留真实Gemma模型文件、原内置模型和历史测量。此题model-only，不退役任何官方model。

## 基线与既有行为

R09 seed提供可真实运行的临时Gemma external model provider，完全独立于R08新模型题。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题先应用 [R09_retired_model](../fixtures/R09_retired_model/manifest.json)；seed是待退役功能的可信起点，不是考生交付。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 应用R09 seed，在fresh process显式注册ext.wp21.retired_gemma，通过其factory真实加载Gemma并做2条capture/identity patch，保留provider与checkpoint的不同身份。 种子before.py只提供单prompt的可用性见证；删除生产provider前，可在本题tests/wp21/R09/内新增薄runner，加载一次provider后对common前2条完成capture和identity patch，并保存独立新leaf。不要重复覆盖种子固定before叶子。
2. 记录provider的活动代码/配置/显式注册入口，说明它只是临时provider，底层Gemma checkpoint仍属于共享只读资源。
3. 删除临时provider实现和活动配置入口，或保留显式retired兼容入口；不改官方Gemma registry。
4. fresh process尝试原provider加载必须失败，list_extensions不得列出该key；不能仅在当前进程清空registry。
5. 从models.gemma2_2b_base.gemma2_2b_base.load_model直接加载官方Gemma，包装公共ModelAdapter，在相同prompt上真实capture/identity patch并对照before底层checkpoint身份；本题全程可为model-only，SAE身份明确为未使用。
6. 验证历史provider运行结果可读且hash不变；shared model/tokenizer/SAE caches保持只读。

## 必须通过的正例

1. before经临时provider真实执行，而非只登记。
2. after fresh process无活动临时provider；旧入口明确拒绝。
3. 官方Gemma model-only加载、capture与identity patch仍真实可用。
4. checkpoint与历史实验bytes不被删除。

## 必须检查的负例

1. 把provider改名但留一个等效旧key入口判失败。
2. 清除shared checkpoint/cache来制造模型不可用判失败。
3. 错误退役models/plugins.py中的Gemma官方key判失败。
4. 只有list变化、旧factory仍正常公开可调用判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
