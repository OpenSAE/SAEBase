# R06 挂载带明确划分的新数据集

把 WP21MiniPairs 接入 SAEBase 的 dataset registry、配置、reader 与真实模型消费流程。输入固定为 24 条原创工程 prompts，不以这 24 条代表任何标准数据集总体。

## 基线与既有行为

仅 register_dataset 不足以挂载。datasets/prompts.py 在 prompt_file override 前检查名称白名单；datasets/artifacts.py 与 legacy prompt_schema.py 有不同可用性矩阵，必须核对实际调用路线。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. common fixture保持只读。把frozen fixtures/common/prompts.jsonl复制到本题允许目录tests/wp21/R06/data/WP21MiniPairs/gemma2_2b_base/v1/prompts.jsonl，matching manifest也放该v1目录；禁止另建仓库根data/。新dataset canonical ID为WP21MiniPairs；24 records、12 groups，每组两条，train/validation/test分别12/6/6 records且group互不重叠。原文本、sample_id、prompt_group_id、split保持不变。
2. 在物理 datasets/WP21MiniPairs/ 实现读取与注册，增加 conf/dataset/wp21_mini_pairs.yaml；通过已有 register_dataset 注册，统一新 key 在实际 reader、canonical/alias、Gemma 可用性检查路径的解析。
3. 给新数据集生成来源和字节 SHA256 manifest，注明这些是工程 prompts；样本数/ID/组/划分从实际记录重算。
4. 证明 fresh process 的 registry list 可发现 WP21MiniPairs，Hydra 组合 dataset=wp21_mini_pairs 后 cfg.dataset.name 正确且正常配置校验通过。
5. 通过新 DatasetPlugin.setup 读取全部 24 条，检查三个显式 split；随后选 validation 的前 4 条，通过现有真实 Gemma/SAE capture 消费，不用 task.prompt 固定字符串绕过新 reader。
6. run evidence 将每条 capture 绑定读取后的 sample_id、prompt_group_id、split、prompt hash 和 dataset manifest identity。
7. 保持现有 IOI 数据集与已知公共任务的兼容；新数据集 metadata/代码变化只生成候选 Context/Code 差异。

## 必须通过的正例

1. 新 key 经 fresh process 注册、列举、Hydra、validator、reader、真实 capture 闭环全部可用。
2. 总24条，train12/validation6/test6，12个group，无sample或group跨split重叠。
3. 至少4条 validation 输入的真实 capture 与新 reader 输出一一对应。
4. 同样 frozen data/config 再加载顺序、IDs及hash稳定。
5. 已有IOI配置/读取路径仍通过原有检查。

## 必须检查的负例

1. 重复 sample_id、同一 group 分配到两个 split、未知 split 明确拒绝。
2. manifest记录数量或文件hash被篡改明确拒绝，不能只信字符串source。
3. 空prompt、缺失sample_id/prompt_group_id、非字符串prompt明确拒绝。
4. 未知dataset key或任意路径 traversal 不得自动落入新dataset默认值。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
