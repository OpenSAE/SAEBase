# R13 删除 debug_norm 子任务并保留兄弟分支

移除 instructor seed 中 benchmark/debug_norm 的实际执行分支，保留同级reconstruction子任务与原默认benchmark行为。

## 基线与既有行为

本题seed在局部wp21_subtasks模块实现两个真实分支，并将其接入原benchmark operation；不是目录名称模拟。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题先应用 [R13_debug_subtask](../fixtures/R13_debug_subtask/manifest.json)；seed是待退役功能的可信起点，不是考生交付。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 应用R13 seed，它预先提供SUBTASKS debug_norm/reconstruction与真实benchmark operation dispatch；无需R12先完成。
2. 在before.py真实模式分别运行debug_norm和reconstruction，保存同一prompt的真实输出；debug_norm计算activation范数，reconstruction计算MSE。
3. 删除debug_norm的计算实现、dispatch项和活动配置/示例；对旧参数明确拒绝，不能映射为reconstruction。
4. 使用fresh process经registered benchmark task再次运行reconstruction，独立从真实向量复算MSE。
5. 用受限真实BenchmarkConfig验证没有subtask的原默认路线仍工作；保存删除前后的源码与历史产物hash。
6. 当前默认benchmark loader未把task.device传给load_registered，因此默认路线实际使用CPU，即使task.device=cuda。记录实际device、内存与用时，不宣称已走GPU路线；硬件资源不足记为环境阻塞，不越权修改shared runtime或backend runner。

## 必须通过的正例

1. debug_norm曾在before阶段执行真实模型，而后在fresh process明确退役。
2. reconstruction兄弟分支保持同样公式与真实执行结果。
3. 无subtask时的默认benchmark路线保留。
4. 目录可保留历史debug_norm输出，但不能据此声称旧子任务仍为活动能力。
5. 默认benchmark回归记录实际加载device；配置写cuda而实际CPU的差异明确可见，不伪报GPU执行。

## 必须检查的负例

1. 移除一个配置文件但SUBTASKS映射仍能调用debug_norm判失败。
2. 把debug_norm静默重定向到reconstruction判失败。
3. 误删除整个benchmark operation或兄弟reconstruction判失败。
4. 删除历史产物来掩盖行为变化判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
