# R08 挂载真正的新 pretrained 模型

在考试实验作用域挂载 ext.wp21.pythia14m，以真实 EleutherAI/pythia-14m pretrained 权重完成捕获与恒等写回。公开七任务的Gemma模型范围保持；本题验证external provider。

## 具体执行步骤

1. 使用冻结官方source https://huggingface.co/EleutherAI/pythia-14m ，revision=d31f659f077f9ea500c4d7faa999893d7f28cbdf。环境准备者提供已核对的本地snapshot；考生只从该snapshot加载，记录model.safetensors、config及tokenizer文件hash。
2. 实现 models/wp21_pythia14m.py 的显式 factory 与 model-only ExtensionBundle，provider key=ext.wp21.pythia14m；factory使用AutoModelForCausalLM.from_pretrained(local_snapshot,local_files_only=True,use_safetensors=True)及同snapshot tokenizer，CPU float32、eval、关闭梯度。
3. 声明HookSpec为layer2、blocks.2.hook_resid_post、width128；官方config为6层GPTNeoX。使用saebase.extensions.register_extension显式注册，import模块本身不自动执行下载/加载/注册。
4. 适配HFHooksModel的GPTNeoX层路径gpt_neox.layers；可用局部subclass或对既有backend做小范围扩展，保留原model.layers和transformer.h行为。
5. 配置文件的filesystem/model slug使用wp21_pythia14m，provider_key单独记录ext.wp21.pythia14m；不要把含点provider ID作为runtime的受限路径片段。
6. 在fresh process显式注册后，经external_model(key).factory加载、包装ModelAdapter，对common前4条prompt调用tokens、forward_logits、capture、assert_identity_patch。
7. 保存每条真实tokens、128维activation、logits及恒等误差，rtol=1e-4、atol=1e-4；同时确认官方registry未添加该实验key。
8. 本题不使用SAE，evidence中的sae明确为未使用；不能调用需要model+SAE的load_external_pair后虚构SAE来凑接口。

## 必须通过的正例

1. 实际模型架构GPTNeoXForCausalLM、层数6、宽128，来自固定pretrained文件且state/filehash一致。
2. 四条capture均由真实HF forward hook得到，shape为128且finite。
3. 恒等写回真实logits满足冻结容差。
4. 显式registration之前provider不可发现，之后可发现；重复注册被拒绝。
5. 既有两种HF层路径兼容且官方七任务模型范围未扩容。

## 必须检查的负例

1. 使用from_config、随机权重、toy、已有模型换alias均不能通过真实挂载验收。
2. 错误revision/hash或缺失snapshot必须失败，不能自动联网切换main/latest。
3. 未知layer、错误hook、声明width与实际不符必须拒绝。
4. 重复provider ID不得覆盖先前注册。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
