# R05 删除临时完整 code 导出功能

删除题目 seed 提供的完整 SAE codes 诊断导出功能，并证明标准 capture 仍可真实运行。删除对象仅是已标明的实验诊断出口。

## 基线与既有行为

仅本题 instructor seed 提供临时 full-code export；每位 agent 都从相同 baseline 加本题 seed 开始，无需依赖 R01–R04。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题先应用 [R05_diagnostic_export](../fixtures/R05_diagnostic_export/manifest.json)；seed是待退役功能的可信起点，不是考生交付。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 按 fixture manifest 应用本题 seed；在独立进程执行 tests/wp21/R05/before.py 的真实模式，使用一条固定 prompt 保存原诊断完整 codes 产物和 source hashes。
2. 阅读 seed 中诊断 wrapper、配置与显式入口关系，列出拟删除的导出 API/开关，确认标准 capture 不属于删除目标。
3. 删除诊断代码、配置和可发现入口；可以保留一个明确报 retired 的兼容入口，但其中不得保留导出实现或成功返回旧 payload。
4. 用 fresh process 调旧入口/旧配置，确认明确报错或 retired 状态，不能忽略旧开关后返回成功。
5. 再用原标准 capture operation 对相同真实 prompt 运行，确认正常 top_features、active_count 等结果保持。
6. 历史 before 诊断产物作为考试证据保留；后续标准 capture 的序列化产物不再包含完整 codes 数组。

## 必须通过的正例

1. before 证据由真实 model/SAE capture 生成。
2. after fresh process 的旧诊断入口不可继续导出完整 codes。
3. 标准 capture 的真实结果与删除前兼容，保留 top_features 摘要。
4. 代码 diff 只移除指定实验功能，历史 before 产物及其 SHA256 不变。

## 必须检查的负例

1. 旧配置或旧参数仍可悄悄导出完整 codes 判失败。
2. 通过删除 saebase.api.capture_features 或剪除标准 capture 规避诊断导出判失败。
3. 通过清理历史实验输出模拟功能删除判失败。
4. 仅修改测试 fixture 的预期、注释或文档而保留活动导出路径判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
