# R03 新增真实 token_position 参数

为 capture 新增 token_position 参数，使同一 prompt 可选择明确 token 的 activation，默认仍为最后 token。参数必须传到 ActivationSite 而非仅写进日志。

## 基线与既有行为

当前 task 的 _pair 返回 profile 默认 site，capture operation 未暴露选择 token 的配置；public ActivationSite 已有 position，可直接复用。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题没有额外instructor seed。

## 具体执行步骤

1. 新增 task.token_position，默认 -1；仅接受非 bool 整数，合法范围为 [-L,L-1]，L 为实际 tokenizer 输出 token 数量。
2. 在 capture operation 构造相同 layer/hook、指定 position 的 ActivationSite，保留共享 tasks.sae_runtime 与 runtime 路径模块不变。
3. 对 common/prompts.jsonl 的前两条记录分别运行 -1 和 0，完整保存实际 token IDs、requested_position 与归一化 resolved_position。位置 0 明确指 tokenizer 输出中的第一个 token，包含其原有 BOS 规则。
4. 通过公共 ModelAdapter.capture 对相同 token IDs 与 site 重新取得 activation，验证 task 真正使用指定位置。
5. 参数与 resolved position 进入配置/运行身份；若本题 runner 使用缓存，position 必须进入 cache identity。
6. 保留默认 -1 的旧字段和原有结果含义。

## 必须通过的正例

1. 两条记录、两个位置得到四条实际结果，每条 resolved_position 与 token IDs 可核对。
2. 任务输出 activation 与公共 API 相同位置的 capture 在冻结容差内一致。
3. 未传参数与显式 -1 等效。
4. 位置改变会改变 site/config identity；不要求所有输入的 activation 数值必然不同。

## 必须检查的负例

1. 位置 L 与 -L-1 明确拒绝，并且没有成功结果文件。
2. true、1.2、null 等非法类型在实际 operation 拒绝，不能截断成整数。
3. 空 token 序列被拒绝。
4. 请求 0 却读取 -1 缓存的结果必须被本题检查发现。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
