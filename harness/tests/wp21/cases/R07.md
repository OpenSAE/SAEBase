# R07 删除临时数据集并保留历史实验

移除 instructor seed 的 WP21RetiredPrompts dataset、别名及活动配置依赖，使新运行无法选择它，同时历史数据与真实结果继续可读。

## 基线与既有行为

此临时dataset由本题seed显式注册；不能删除五个内置dataset，也不依赖R06交付。

基线提交为 `41a54cbfdee5cce24d3d8f7517aadef0c752c5ac`，[原始源码快照](https://github.com/OpenSAE/SAEBase/tree/41a54cbfdee5cce24d3d8f7517aadef0c752c5ac)。运行profile为 `gemma_inference`。本题先应用 [R07_retired_dataset](../fixtures/R07_retired_dataset/manifest.json)；seed是待退役功能的可信起点，不是考生交付。

## 共同执行规则

机器定义是 [cases.json](../cases.json) 中同 ID 的对象；本卡按该对象生成。治理与资源语义见 [REAL_WORKFLOW_PROTOCOL.md](../../../../harness/contracts/REAL_WORKFLOW_PROTOCOL.md)。本题当前为 **DESIGN_READY**，不表示本环境已经拥有checkpoint，不表示考生或独立评审已经执行通过。

每位agent从固定源码快照加本题seed独立开始，使用自己的candidate workspace；其它agent的代码和产物均不是依赖。产品代码仅可修改本卡允许路径；同题runner与自测放 `tests/wp21/<case_id>/`。实验数据与结果保持在该candidate的规范 `experiment/<dataset>/<model>/<task.path>/<sub_name>_<seed>/` 内。证据放 `harness/tests/wp21/runs/<run_id>/<case_id>/`。下面的必需交付是逻辑文件名；真实实验产物保留规范目录，并由evidence和artifacts_manifest列明确切相对路径，无需为满足名称而复制大文件。

对新增API/参数/入口，在report记录输入类型、默认值、范围、错误与返回结构。Expected Code Diff在修改前写；Observed依据修改后源码与实际运行，不得将Expected复制为Observed。新节点/参数/术语使用双语候选Context和Code信息；候选审阅状态保持unchecked，所有正式Tree、harness规则、评分器、fixture与原历史记录均受保护。没有产品变化的题目明确交付空产品diff及不变的候选说明。

每次实际命令用题包record工具留argv、stdout、stderr、exit_code及计时；在selfcheck逐条映射本卡正反例。缺依赖、checkpoint或资源时保留ENV_BLOCKED与可复现原因，不能替换成toy。小型synthetic张量可验证异常分支，完整正例必须使用真实pretrained模型。输入为原创工程prompt也要保留其source/IDs/split，不把它描述成完整科学数据集。

授权范围止于本题隔离本地工作；所有删除仅限题目明确的临时能力或owned run。共享权重缓存只读、历史结果不可变，网络下载由冻结环境准备流程处理。本轮不执行远端push/PR/merge/deploy。

## 具体执行步骤

1. 应用 R07 seed；使用 before.py --help 确认参数后，以 frozen dataset fixture 通过 seed 的真实 DatasetPlugin.setup 消费至少2条输入并进行真实Gemma capture。
2. 保存 canonical key WP21RetiredPrompts、alias wp21_retired_prompts、配置与引用依赖清单，以及before数据/结果/源码hash。
3. 删除本题实验dataset module、活动注册入口与配置引用；对于保留的兼容入口应明确返回 retired 错误。
4. 在 fresh process 重新加载可用组件，确认 get_dataset_plugin 对 canonical与alias均拒绝，list_registered_dataset_keys 不含临时key。
5. 对原有IOI或本题shared prompt原始数据执行至少1次真实Gemma capture，以证明核心路径保留。
6. 重读before的dataset文件、manifest、capture产物，字节hash不变；移除旧key的运行支持不等于销毁历史数据。

## 必须通过的正例

1. before阶段实际从seed dataset读取并由真实Gemma消费。
2. after fresh process canonical和alias都不可作为活动dataset运行。
3. 所有活动配置/入口对旧key不再宣称可用；历史说明可保留并标retired。
4. 历史原始数据与已完成结果字节完整，标准baseline仍执行成功。

## 必须检查的负例

1. 只删配置而显式registration函数仍能成功挂载同名旧dataset判失败。
2. 只删canonical但alias仍解析成功判失败。
3. 只清空当前进程private registry，不变更活动入口判失败。
4. 误删shared common prompts、其它dataset或历史实验目录判失败。

这些验收条件在出题时冻结。评分者可以用不同合法输入重放同一条件，不能看过考生实现后新增需求。
