# SAEBase v0.6.5 — Auditable Agent Research Workflows

SAEBase v0.6.5 makes it easier to develop, evaluate, and maintain sparse autoencoder research workflows with coding agents. The release builds on SAEBase's existing model, activation, intervention, benchmark, and experiment interfaces and adds a more complete process for reviewing work against real execution evidence.

## What's new

- **Research tasks for coding agents.** Define a bounded task, work in a separate project workspace, and use the existing SAEBase interfaces to update components or run experiments.
- **Independent verification.** Reviewers can run positive and negative checks in a fresh workspace instead of relying on an agent's own success report.
- **Traceable experiments.** Record input and checkpoint identities, executed commands, source changes, and output files so research work can be inspected and reproduced.
- **More useful diagnostics.** Distinguish implementation, environment, and evaluation problems; preserve failed attempts and historical reviews.
- **Browsable project context.** Explore architecture, research knowledge, code, environment information, and terminology through the source-backed Atlas.

## Getting started

Python 3.11 or 3.12:

```bash
git clone --branch v0.6.5 https://github.com/OpenSAE/SAEBase.git
cd SAEBase
python -m pip install -e .
python saebase/examples/quickstart/public_api_offline.py
python saebase/examples/quickstart/first_experiment.py --output runs/first-experiment
```

For real pretrained model and SAE experiments, install `.[analysis]` and obtain the corresponding upstream weights. For agent-assisted development, use the **full source checkout** with the [Research Harness guide](../../README.md) and your coding-agent environment. The Python wheel alone does not install the complete set of agent rules, Atlas sources, and review utilities.

## Verification and scope

The v0.6.5 release candidate must pass the exact-source CI checks for both supported Python versions, package building, dependency installation, localization, and code quality. The manual release gate then verifies the wheel, source archive, checksums, and immutable Git tag.

The [Harness phase closeout](../../github_work_plan/21_harness_phase_closeout_20261030.md) records independent reviews of small SAEBase engineering tasks. Across two rounds, 18 of 20 distinct tasks had recorded passes; the remaining results and their causes are retained, not silently revised. These outcomes show which specific tasks were checked, **not** a general success probability for autonomous agents or a guarantee of scientific correctness.

Some training reproducibility and benchmark execution findings remain separate product-level follow-ups. The release keeps original task grading and historical experiment records unchanged.

The release package is checked for a clean installed-wheel import of the source-owned dataset modules under `saebase.datasets`, in addition to the nine public CLI commands. The source checkout retains the physical `datasets/` project tree. These checks guard against namespace gaps between editable installs and published wheels.

## Compatibility and distribution

- Retains the existing public SAEBase Python API, nine CLI entry points, and supported Python 3.11/3.12 environment.
- Source-controlled Harness is available from the tagged GitHub repository; the Python package provides the SAE research APIs and runtime.
- The GitHub software Release contains a tested wheel, sdist, `release-evidence.json`, and `SHA256SUMS`.
- No upstream model or SAE weights, private datasets, raw GPU artifacts, or secrets are redistributed. There is no implied PyPI publication or hosted GPU service.
