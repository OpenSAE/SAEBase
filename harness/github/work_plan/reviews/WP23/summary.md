# WP23 · 人类审阅摘要

## 概览

WP23 旨在把 Dataset、Model、SAE 与科研任务的真实预检建设为可复用能力，以 WP22 固定的 QA500 组合做首次系统验收。当前只审阅设计、预算和源码影响，不运行 GPU，不批准下载或发布。

## 1. 目标、科研价值与 Atlas 定位

目标是让每个指定组件及有效组合都能进行有界检查并形成独立诊断收据，为后续真实研究提供可信的前置条件。Atlas 只承担长期知识与来源定位，具体实验范围保留在计划中。

## 2. 真实源码状态、前置阻塞与所有权

现有 Precheck 已具备 SAE 最小检查与审计接口，但缺少 Dataset、Model 独立检测和跨组件矩阵输出。WP22 与新主分支存在旧接口差异；修复必须由真实源码所有者承担，不新增平行框架。

## 3. 冻结的 WP22 测试人口与判定单位

测试对象固定为十个问答数据源、十个模型和二十个 SAE 层位点，再形成一百个模型数据组合、二百个位点数据组合。每个数据源验证五百条真实输入；预检只抽取少量固定问题，不改变科研协议。

## 4. 执行 DAG、阶段门槛与局部失败规则

按源码对齐、实现、离线验证、环境准备、独立组件、组合检查、最小任务、审计、交付的依赖顺序执行。单个组件受阻只影响其依赖组合，其余工作继续；任何失败都必须生成可核验收据。

## 5. Setup、硬件与实际预算

从干净机器调查 Python、CUDA、内存、磁盘、依赖和资源访问；Setup 仅准备环境与缓存，不执行科研计算。真实 GPU、网络下载及总预算均需逐项授权，先测量再决定，禁止通过更换科学条件绕过阻塞。

## 6. 结果矩阵、审计与安全恢复

输出组件、兼容组合、任务检查与覆盖率四张表，并保存逐项原始收据、配置哈希、运行来源与审计结果。恢复时核对身份后复用有效结果；证据完整可以审计通过，但执行失败和科研验收仍单独标记。

## 7. 负面测试与独立接收标准

必须验证缺权重、受限数据、重复记录、错误层位点、维度不符、无效输出、资源不足、收据丢失和来源变化等反例。离线软件检查与真实模型测试分别验收，不以形式上的测试通过代替科学证据。

## 8. Atlas / Harness 与具体科研方案隔离

通用检查归现有任务与运行模块，具体 QA500 选择归实验配置；禁止将任务编号、数量和执行步骤加入长期节点说明。计划引用现有 Atlas，节点是否真的需要变化要由独立源码影响审计判断，源码修改权限另行审查。

## 9. 执行指引与结构化绑定

工作单保存已确认的人类意图、现有 Context 与合同 ID、任务依赖和预定义交付指标。新流程先向人类展示逐节摘要，再交付六域影响审计；通过范围审核之前仅能讨论和修订草稿，不启动正式实验。
