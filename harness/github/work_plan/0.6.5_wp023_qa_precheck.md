# WP23 · Independent Component Precheck

> AGENT READY FOR LOCAL VALIDATION · SOFTWARE HANDOFF ONLY · NO AUTOMATIC GPU/NETWORK/PUBLISH AUTHORIZATION

## 1. 研究与工程目标

独立建设可复用的 Dataset、Model、SAE、Compatibility 和最小 Task 真实 Precheck。每个被声明的真实组件及合法组合都必须产生可验证的 PASS、FAIL、BLOCKED 或 NOT_RUN 收据，能够恢复和审计。它验证实验前置条件，不给出模型性能或 SAE 科学效果结论。不建立平行 Registry、数据层或 Runtime。

本计划的 GitHub 源码准备和轻量 CI 已完成，正式交给 Local Agent 验证真实环境、组件、兼容性、阻塞恢复和整套 Audit。Agent Ready 表示工具已可启动检查，**不等于模型、数据、Benchmark 或 Resume 的真实测试已 PASS**；实际计算、下载和付费权限另行授权。

## 2. 实际源码和所有权

`saebase/registry.py` 负责 Dataset/Model/Task 注册；Model 配置负责所拥有 SAE profiles；`tasks/precheck/operation.py`、`worker.py`、`sae_checks.py`、`report.py` 提供现存单项执行及结果处理。当前 main 已包含 Dataset-only、Model-only、合法组合规划、隔离 Worker、批量编排、独立启动器和结果审计源码；这些组件的**真实权重、数据及完整恢复表现**由本任务 Local Agent 逐项检验。已知 Benchmark 所需外部配置不足时应明确 BLOCKED，不得伪造 PASS。

| 责任 | 拟新增或修改位置 |
| --- | --- |
| 独立 Dataset 验证 | `tasks/precheck/dataset_checks.py`、`tests/precheck/test_dataset_checks.py` |

以上仅列候选文件，不授权源码写入；新增路径必须复用正确的 Dataset/Model/Task/Runtime 所有者。不存在的文件不得在 Atlas Code 中冒充已实现模块。

## 3. WP23 独立默认检查规则

通用默认归 `conf/task/precheck.yaml`，本任务执行选择归 `conf/experiment/wp23_precheck.yaml`。由当前权威 Registry 发现**全部活跃** Dataset 和 Model，并从每个 Model 声明的 SAE profiles 稳定排序选择**最多两个明确 Site**；没有真实 Site 则记录 BLOCKED/NOT_RUN。清单保存准确 ID、来源与排除原因，不靠外部任务计划提供对象或参数。

默认执行检查：① Registry / asset inventory（CPU，只读）；② Dataset 真实源 revision、split、字段、sample ID、prompt/answer 与摘要；③ Model tokenizer、权重身份、native forward、logits 形状和有限性；④ SAE checkpoint、精确 layer/hook、d_in/d_sae、真实 activation→encode→decode、L0 与 reconstruction MSE；⑤ 有效 Model–Dataset 与 Site–Dataset 的逐项真实兼容性；⑥ 已通过组合上的 Capture、Intervene、Generate、Benchmark 最小 smoke。Circuits、Explain、Train 不在默认真实执行之内，Native 另行审批。

每对最多 2 条确定的真实输入。不存在的资源不模拟成功；组件未 PASS 时其下游组合不能 PASS。必须先枚举所有目标，若超预算则逐项目记录或申请增加预算，不得静默截断。默认不开启 execute、network、download、GPU、native 或 publish。

## 4. GitHub 工程准备及 Agent Ready

GitHub 侧已提交 Dataset / Model / SAE / Compatibility 检查器、隔离 Worker、统一入口、运行收据和审计产物。代码质量和现有 Product / Harness CI 已通过。**完整本机运行、异常恢复、Benchmark 配置是否充足、真实数据/模型是否可加载，正是交给 Local Agent 要执行和报告的测试，不应先要求 GitHub 真实跑完。**

交付依据是：确切的实现提交 SHA、现存可调用入口、自有默认配置校验、明确的运行阶段、源代码级负面保护和成功的轻量 CI。真实环境下失败、BLOCKED 或需要新工程修复的情况，必须如实记收据并报告；不让 Local Agent 临时设计新框架或伪造成功。

## 5. Local Agent 执行 DAG

在 Local Agent 环境按 Setup（纯本地环境探测）→ Inventory → 可选 Asset Prepare（需单独网络授权）→ Dataset 和 Model → SAE → Compatibility → Task → Audit → Handoff 执行。Asset Prepare 不阻断使用已合法缓存的真实资产；Setup 不进行科研计算；各独立检查在真实 Worker 隔离运行，局部失败只阻塞依赖组合。每项检查写独立 receipt；崩溃、超时或无收据时监督进程补记真实 FAIL/BLOCKED，不允许隐式省略或伪造 PASS。

本任务的 `workplan-json.steps` **只含 Local Agent 的运行阶段**，不包含 GitHub 产品研发阶段。每个阶段已绑定仓库中真实存在的 CLI；Local Agent 不必自行开发 Launcher 或改动产品源码。Audit 和 Handoff 必须在组件失败或阻塞后仍尝试生成真实失败报告，因此其执行不以全部被检查项 PASS 作为前置条件；这是结果收集步骤，而非检查通过门禁。

## 6. Setup、资源上限与授权

干净机器先进行不联网的 Linux、Python、Torch/CUDA、驱动、显存、内存、磁盘与关键 import 检查；需要安装或准备资产时单独请求联网和下载授权，并验证依赖解析及 `pip check`。网络、下载、GPU、付费预算、Native、远端备份与发布均分开批准。推荐最小预算为每个兼容目标 2 条真实输入、每 Worker 最多 128 token、180 秒；先根据声明目标估计总运行时间和磁盘预算，再请求运行许可。

OOM 只可在同一 Model、SAE、输入、dtype 与指标身份下有界恢复；不通过换权重、量化、替代样本或改科研协议来通过 Precheck。资源不足要明确 BLOCKED，不能推断其他设备的运行结果。

## 7. 结果矩阵、Resume、Audit、独立验收

单次运行输出至 `experiment/_studies/wp23_component_precheck/reports/<run_id>/`。必须提供 `component_checks.csv`、`compatibility_checks.csv`、`task_checks.csv`、`coverage_summary.csv`、`artifact_manifest.json`、`audit.json`、`archive_receipt.json`、`workplan_completed.md`，连同每个组件、组合和 Task 的原始收据。

Resume 比对 source SHA、配置、Dataset 记录、Model/SAE checkpoint、Layer/Hook、Worker 参数与收据哈希，只复用确切一致的有效结果。证据完整性、真实执行状态、科学验收分别报告；即使 FAIL/BLOCKED，只要故障收据完整仍可独立通过证据完整性审计，不能称为科研合格。缺行、哈希错误、额外伪收据必须阻止归档。

## 8. Atlas 与 Human Review

Atlas Code、Knowledge、Environment、Core、Harness、Context 各自审计。只有可观察的长期职责或性质改变才调整节点，任务参数不进入长期节点。Code 新模块未实际实现前影响记为 DEFER；已有节点功能不变时保持 NONE，实施后按真实 AST 检查。确实有 ADD/CHANGE/REMOVE 才提交 Node Human Check。

人类已审阅计划并授权列明的 GitHub 源码准备，相关 PR 已在 CI 通过后合并。**本次不申请 Atlas 节点增删改，故无 Node Human Check 页面；源码与长期 Code Node 的关系已据当前代码复核。** GPU、网络、模型下载、Native、远端备份和发布仍不由 Agent Ready 自动授予。

## 9. 结构化合同与交接条件

WP23 为独立 `local_agent` 类型，软件交付状态为 `agent_ready`；本地真实组件测试和科学验收尚未运行，必须由 Local Agent 在执行收据中逐项注明。预期交付 E1–E7 依次检查 Dataset、Model、SAE、两类合法 Pair、Task 与审计/恢复，实际数量按本任务声明的 Registry manifest 为准。绝不把某种 mock、配置文件存在或 CI 成功替代真实 GPU 科学验证。


### Local Agent 单命令交付

在新机器上取得当前 SAEBase main 后，先阅读 `AGENTS.md` 与本文。唯一执行入口为已实现的 `scripts/workplan/wp023.sh`；无需本地 Agent 编写新脚本。使用未占用的 run ID，并按机器许可和预算选择授权参数。

```bash
# 不联网检查真实环境和当前独立默认配置
bash scripts/workplan/wp023.sh setup

# 只查看 Registry 中声明的组件，不执行真实模型计算
bash scripts/workplan/wp023.sh inspect

# 先在无额外执行权限的条件下完成可用范围的检查并交付阻塞报告
bash scripts/workplan/wp023.sh run --run-id wp23_run_01

# 当人类另外明确批准 GPU/计算预算、且必要资产真实可用后：
bash scripts/workplan/wp023.sh run --run-id wp23_gpu_01 --allow-compute --allow-gpu

# 需要补齐依赖或资产时另行申请网络、安装、下载权限与下载字节预算：
# bash scripts/workplan/wp023.sh asset_prepare --allow-network --allow-install
# bash scripts/workplan/wp023.sh asset_prepare --allow-network --allow-download --assets-json /path/to/approved_assets.json --max-download-bytes 1000000000

# 对未完成的相同 run ID 检查，观察 Resume 的真实行为而非预先假定成功
bash scripts/workplan/wp023.sh resume --run-id wp23_gpu_01 --allow-compute --allow-gpu
```

每次 `run` 都尝试按真实阶段输出收据、四张 CSV、`audit.json` 与填写完成的 `workplan_completed.md`；`handoff` 单独验证交付文件齐备。**Local Agent 应实际测试**：已成功记录的复用；权限或资产变化后原阻塞是否可安全恢复；真实 Benchmark 是否具备必要配置；缺权重、CUDA/OOM、收据缺失、配置变化和复核等结果。遇到已知权限阻塞重跑限制，必须使用新的 run ID 并记录问题，不能默默把旧阻塞写成 PASS。不要为了让测试变绿而自行改变科研条件。
