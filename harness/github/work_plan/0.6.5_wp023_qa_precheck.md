# WP23 · Independent Component Precheck

> DRAFT · HUMAN REVIEW PENDING · NOT AGENT READY · NO GPU/NETWORK/EXECUTION/PUBLISH AUTHORIZATION

## 1. 研究与工程目标

独立建设可复用的 Dataset、Model、SAE、Compatibility 和最小 Task 真实 Precheck。每个被声明的真实组件及合法组合都必须产生可验证的 PASS、FAIL、BLOCKED 或 NOT_RUN 收据，能够恢复和审计。它验证实验前置条件，不给出模型性能或 SAE 科学效果结论。不建立平行 Registry、数据层或 Runtime。

本文件是第 3 阶段的起草方案，不是可执行任务。先完成 GitHub 端产品模块、配置、入口、测试及集成，再独立通过 Agent Ready 门禁，最后交给 Local Agent 在真实机器执行。

## 2. 实际源码和所有权

`saebase/registry.py` 负责 Dataset/Model/Task 注册；Model 配置负责所拥有 SAE profiles；`tasks/precheck/operation.py`、`worker.py`、`sae_checks.py`、`report.py` 提供现存单项执行及结果处理。尚未在 main 证明完整的 Dataset-only、Model-only、兼容组合和批量编排能力；缺失接口必须在 GitHub 准备阶段实现。

## 3. WP23 独立默认检查规则

通用默认归 `conf/task/precheck.yaml`，本任务执行选择归 `conf/experiment/wp23_precheck.yaml`。由当前权威 Registry 发现**全部活跃** Dataset 和 Model，并从每个 Model 声明的 SAE profiles 稳定排序选择**最多两个明确 Site**；没有真实 Site 则记录 BLOCKED/NOT_RUN。清单保存准确 ID、来源与排除原因，不靠外部任务计划提供对象或参数。

默认执行检查：① Registry / asset inventory（CPU，只读）；② Dataset 真实源 revision、split、字段、sample ID、prompt/answer 与摘要；③ Model tokenizer、权重身份、native forward、logits 形状和有限性；④ SAE checkpoint、精确 layer/hook、d_in/d_sae、真实 activation→encode→decode、L0 与 reconstruction MSE；⑤ 有效 Model–Dataset 与 Site–Dataset 的逐项真实兼容性；⑥ 已通过组合上的 Capture、Intervene、Generate、Benchmark 最小 smoke。Circuits、Explain、Train 不在默认真实执行之内，Native 另行审批。

每对最多 2 条确定的真实输入。不存在的资源不模拟成功；组件未 PASS 时其下游组合不能 PASS。必须先枚举所有目标，若超预算则逐项目记录或申请增加预算，不得静默截断。默认不开启 execute、network、download、GPU、native 或 publish。

## 4. GitHub 工程准备及 Agent Ready

第 7 阶段由 GitHub 责任人按真实源码所有权完成 Dataset / Model / SAE / Compatibility 检查器、Runner 和 Worker 集成、本任务 Launcher、Resume、Audit、统一报告及 CPU 负例测试。所有命令与接口必须真实存在、可复用、可静态检查，Python 环境安装、关键 import、格式测试、exact-head CI 和独立负面测试完成后才能申请 Agent Ready。

必须分别具备：准确 commit SHA、可执行逐阶段命令、默认配置、目标声明与归档 schema、超时/缺收据/重复/参数变化的测试证据、CI 收据及必要人类审批。正式执行环境中的 GPU/网络/许可仍独立核查，但不得让 Local Agent 临时编写缺失功能。**本 Draft 不把尚未实现的脚本当成已就绪入口。**

## 5. Local Agent 执行 DAG

仅 Agent Ready 后按 Setup → Inventory → Dataset 和 Model → SAE → Compatibility → Task → Audit → Handoff 执行。Setup 仅准备获准的依赖和资源并探测设备，不进行科研计算；各独立检查在真实 Worker 隔离运行，局部失败只阻塞依赖组合。每项检查写独立 receipt；崩溃、超时或无收据时监督进程补记真实 FAIL/BLOCKED，不允许隐式省略或伪造 PASS。

本任务的 `workplan-json.steps` **只含 Local Agent 的运行阶段**，不包含 GitHub 产品研发阶段。每个真实子命令在实现和测试之后写入 `steps[].command`，不让 Agent 自行生成启动器或改动产品源码。

## 6. Setup、资源上限与授权

干净机器检查 Linux、Python、Torch/CUDA、驱动、显存、内存、磁盘、依赖解析、`pip check`、关键 import 和资产访问。网络、下载、GPU、付费预算、Native、远端备份与发布均分开批准。推荐最小预算为每个兼容目标 2 条真实输入、每 Worker 最多 128 token、180 秒；先根据声明目标估计总运行时间和磁盘预算，再请求运行许可。

OOM 只可在同一 Model、SAE、输入、dtype 与指标身份下有界恢复；不通过换权重、量化、替代样本或改科研协议来通过 Precheck。资源不足要明确 BLOCKED，不能推断其他设备的运行结果。

## 7. 结果矩阵、Resume、Audit、独立验收

单次运行输出至 `experiment/_studies/wp23_component_precheck/reports/<run_id>/`。必须提供 `component_checks.csv`、`compatibility_checks.csv`、`task_checks.csv`、`coverage_summary.csv`、`artifact_manifest.json`、`audit.json`、`archive_receipt.json`、`workplan_completed.md`，连同每个组件、组合和 Task 的原始收据。

Resume 比对 source SHA、配置、Dataset 记录、Model/SAE checkpoint、Layer/Hook、Worker 参数与收据哈希，只复用确切一致的有效结果。证据完整性、真实执行状态、科学验收分别报告；即使 FAIL/BLOCKED，只要故障收据完整仍可独立通过证据完整性审计，不能称为科研合格。缺行、哈希错误、额外伪收据必须阻止归档。

## 8. Atlas 与 Human Review

Atlas Code、Knowledge、Environment、Core、Harness、Context 各自审计。只有可观察的长期职责或性质改变才调整节点，任务参数不进入长期节点。Code 新模块未实际实现前影响记为 DEFER；已有节点功能不变时保持 NONE，实施后按真实 AST 检查。确实有 ADD/CHANGE/REMOVE 才提交 Node Human Check。

本次授权仅限重新起草 WP23 正文、人类意图记录、逐节摘要、六域审计与自身 Draft 配置；对代码编辑、节点改动以及任何运行权限还需独立批准。人类审阅通过后再进入 GitHub 工程准备。

## 9. 结构化合同与交接条件

WP23 为独立 `local_agent` 类型，当前 `status=draft`，只有完整 GitHub 准备与独立审核完成后才可标记 `agent_ready`。预期交付 E1–E7 依次检查 Dataset、Model、SAE、两类合法 Pair、Task 与审计/恢复，实际数量按本任务声明的 Registry manifest 为准。绝不把某种 mock、配置文件存在或 CI 成功替代真实 GPU 科学验证。
