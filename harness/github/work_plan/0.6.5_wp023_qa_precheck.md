从 WP22 `datasets.json`、`sites.json` 读取以下声明，而不是在 WP23 再建一套动态清单：

- 10 Model：`gemma270m`、`pythia410m`、`gemma1b`、`qwen3_1_7b_base`、`gemma2_2b_base`、`qwen35_2b`、`gemma3_4b_pt`、`gemma3_4b_it`、`qwen3_8b`、`llama31_8b`；其 20 SAE 位置**必须以 WP22 的精确 `sites.json` 层列表**解析，包含 model_key / sae_key / layer / hook / release / checkpoint。
- 兼容目标：10×10=100 Model–Dataset 和 20×10=200 SAE Site–Dataset；Precheck 每组合使用固定冻结问题中的最多 2 条真实 QA 输入，而不是两个额外合成数据、不是 500 题正式结果，也不是 10 题 WP22 Pilot。检查所有 300 个**声明目标的状态收据**，并非要求 300 次必定成功。

- 真实运行总耗时、可用 VRAM、安装磁盘、逐 Worker 超时阈值、分布式设备分配先测量、后做独立预算决策。**当前 Workplan 不提供无证据的小时数/费用保证。** Native Circuits/Train 和自动 B2/HF 全部不在本次测试许可内。

## 7. 负面测试与独立接收标准

1. Dataset：缺数据源、gated 403、错误 revision/split、少于 500 条、重复 ID/Prompt、错误 label 或 gold 泄漏。
2. Model：未知 key、明确 Legacy 模型、tokenizer/chat template 不兼容、权重身份变化、无 CUDA、OOM、无前向但伪 PASS。
3. SAE：不属于该 Model 的 SAE、错误 hook/layer、不同 `d_in`、无效 feature 索引、NaN/Inf、保存的 checkpoint SHA 变化、仅存在文件但未 encode。
4. Compatibility：Model 输入与某 Dataset schema 不适配、超过 2048 token 的固定问题，S5 上游 BLOCKED 不阻止其它可执行组；没有真实问题时不能合成替代。
5. Worker/Resume：超时、无收据、重复任务、半写 JSONL、不同 commit/protocol 恢复、重复输出、线程/进程误共享 GPU；全部留下独立解释。
6. Audit：未声明目标、哈希篡改、逃逸路径、缺报告、收据与 run_id 不符、执行 FAIL 但收据齐全、`archive=false` SKIPPED、已有 tar 不得覆盖、远程自动上传被拒。
7. 独立接收：CI 检查 exact head、真实 GPU 原生执行有设备/Checkpoint/Token 证据、审计可重放；全部非通过组合依然逐一交付说明。人工检查前不得称为 RELEASE_READY 或正式 WP22 GPU 合格。
